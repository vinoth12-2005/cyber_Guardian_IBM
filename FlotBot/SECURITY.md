# FloatBot AI — Security & Hardening Policy

## 1. Security Architecture & Threat Model

FloatBot is designed to run directly on endpoints to detect and mitigate malicious activity. As a security product, FloatBot enforces rigorous self-protection and hardening controls.

---

## 2. Hardening Measures

### 2.1 AI Prompt Injection Defenses
- **Boundary Tagging**: All external untrusted strings (OCR text, downloaded file names, command-line arguments, URL query strings) are sanitized and wrapped inside `<untrusted_external_data>` tags before being passed to AI models.
- **Strict Analyst System Prompts**: Models are instructed never to execute instructions, commands, or identity alterations contained inside `<untrusted_external_data>` blocks.
- **Automated Injection Benchmarks**: The `AIBenchmark` test suite continuously validates model resilience against jailbreak and command injection payloads.

### 2.2 Response Engine Safety & Privilege Containment
- **Zero Arbitrary Execution**: FloatBot does NOT execute arbitrary shell commands generated by LLMs.
- **Allowlisted Actions Only**: Only predefined, strictly validated functions in `SafeActionExecutor` can be executed (`collect_evidence`, `calculate_hash`, `quarantine_file`, `restore_file`, `terminate_process`, `block_indicator`, `create_incident`, `export_report`).
- **Core OS Process Protection**: PID 0, PID 1, and critical system daemons (`systemd`, `init`, `launchd`, `csrss.exe`, `lsass.exe`, `services.exe`, `wininit.exe`) cannot be terminated under any circumstances.
- **Explicit Consent Tiers**: All `MODERATE` (process kill, file quarantine) and `HIGH_RISK` (firewall blocks) actions require explicit operator confirmation before execution.

### 2.3 Quarantine Vault Encryption
- Files moved to quarantine are encrypted with **AES-256-GCM** before storage in the quarantine vault (`.flotbot/quarantine/`).
- File permissions on the original path are removed and original filenames obfuscated to prevent accidental execution.

### 2.4 Cryptographic Audit Trail
- All operations (detections, approvals, remediations, configuration changes) are recorded in the `audit_logs` SQLite table.
- Each record includes a cryptographic SHA-256 hash linked to the previous log entry. Any manual database tampering breaks verification immediately (`auditLogger.verifyIntegrity()`).

### 2.5 Secrets & Key Hygiene
- API keys (`GEMINI_API_KEY`, `VIRUSTOTAL_API_KEY`) are loaded only from backend environment variables and are never bundled in client renderer distributions or logged to standard output.
- `.env.example` contains only non-sensitive placeholder templates.

---

## 3. Reporting Vulnerabilities

If you discover a security vulnerability in FloatBot, please report it via confidential security advisory or email to `security@flotbot.local`.
